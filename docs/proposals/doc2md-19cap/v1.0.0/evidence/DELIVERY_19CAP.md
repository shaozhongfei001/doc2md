### 补注：一条最容易说错的话——L35 的"作废"没有发生

L35 完成的是 **"算得对、报得出"**，不是 **"已经作废了"**：

| 事实 | 含义 |
|---|---|
| `stale_candidate_evidence` 只在 `correction.py` 产出、`CorrectionOutcome` 承载、`to_mapping()` 序列化 | 它是**清单**，不是副作用 |
| `mark_stale(candidates, *, revoked_source_ids)` 吃的是候选 dict + 源版本 id，**不吃 id 列表** | 想直接拿清单去标记会失败 |

正确说法：**"纠错后能算出并报出应作废的证据清单。"**
错误说法："纠错后证据会被作废。"——后者把可计算性说成了已完成的副作用。

## 5. 工程约束（本文档唯一带有规范性质的部分）

四轮返工（L23 → L25 → L26 → L27）的根因不是四个 bug，而是**同一事实被推导两次、且两次之间没有断言**。
由此形成的约束，采用 QA 建议的三档版本（原始"禁止第二套实现"的字面写法会误伤性能路径与多输入域）：

> **同一个事实只允许一个权威推导源。** 若必须存在第二套推导，只能是以下之一：
> 1. **显式拒绝** —— 第二套根本不必存在时（删除降级路径即此档）；
> 2. **交叉校验** —— 第二套必须存在时（覆盖另一输入域、或性能路径），必须有一条断言把两者输出绑死。
>
> 禁止的只有第三种：**静默降级** —— 无提示地让第二套产出与第一套不同的事实。

配两条判定问句（比原则本身更好用）：

1. **这套实现产出的是同一个事实，还是不同输入域各自的事实？** 前者必须收敛，后者允许并存。
2. **有没有一个夹具能区分这两套？** 一个都无法区分的第二套就是负债，必须删除。

现有正面样例：`test_recomputed_structure_matches_the_extractor_record`（`recomputed == recorded`），
两套推导被一条断言绑死，因此是资产而不是负债。

**反面样例（本仓库真实发生过）**：`L23` 把"已知证据集"实现成注释子集，与提取器口径并存且无交叉校验，
结果是合法表格被拒；`L25` 修它以 `cells` 反推，又因同样理由漏掉整行、造出幽灵 id。

## 8. 验收判据本身（这轮长程最可复用的产出）

判据被修正过两次，每次都是因为**旧判据能被一句话骗过**：

| 版本 | 判据 | 它防的错法 |
|---|---|---|
| v1 | 代码里有这个检查 | 无（读起来安全即可） |
| v2 | 有变异能让这个检查变红 | 守卫声明了却从未被执行 |
| **v3（现行）** | v2 **+** 三坐标：变异原文 / 变红用例 node id / 失败行号与表达式 | **v2 本身变成一句声明** |

> **声明了却没有被执行过的守卫，等于没有守卫；它只是让代码读起来更安全。**
>
> 而"我做过变异验证"如果不附三坐标，也只是第二层声明。
> 本轮能定论，不是因为作者与 QA 互相信任，而是双方各自独立拿到了
> `test_correction.py:818`、`Failed: DID NOT RAISE` 这类**可对照的坐标**。

配套两条操作规则（均由真实失误换来的）：

1. **范围断言钉在提交的父提交上**（`git show --stat <sha>`），不钉"我上一轮记得的 HEAD"——
   否则基准选错会让你把"不符合"读成"我记错了"；
2. **先证变异已落盘，再怀疑缓存**——`md5sum` + `git diff --stat` 之后仍绿，才去想别的。
