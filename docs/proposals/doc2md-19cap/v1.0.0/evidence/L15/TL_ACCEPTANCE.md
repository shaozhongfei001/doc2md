## 1. 处置的是什么

`L14-FIND-02`：无表格文档的脚注**文本不进任何产物**，只剩一条 `NOTE_WITHOUT_REFERENCE` issue。
契约的 `notes` 挂在 `Table` 上，**没有文档级安置位**——这不是漏写代码，是契约缺位。

两条路：

| 方案 | 代价 |

| **fail-closed 拒绝** | 此类文档暂时不可处理，但不会产出"少脚注却看起来完整"的包 |

选了后者：**暂时不能做，好过做错**。

## 3. 三种输入的实测行为

| 输入 | 结果 |
|---|---|
| 无表格 + 有脚注（含无引用的孤儿脚注） | **`E_REVIEW_REQUIRED`**，detail 列出 `note_ids` / `note_ref_ids` |
| 有表格 + 无脚注 | 放行，`tables=1, notes=0` |
| 空文档（无表格无脚注） | 放行，`tables=0, notes=0`，packet 仍写明"未检出原生 Word 表格" |

第三条是关键：**不能一刀切**。"空文档是合法输入，且'该文档没有表格'是一句真实的陈述"——
如果为了防丢脚注把所有无表文档都拒掉，就会把合法输入误杀，这比原来的漏洞更难发现。

## 4. 代价（如实登记）

| 编号 | 内容 |
|---|---|
| `L15-LIM-01` | 无表文档的脚注**暂时无法处理**，用户会收到拒绝而非结果 |
| `L15-LIM-02` | 拒绝依据是"有候选脚注"，若 `read_notes` 对某版本 Word 的脚注漏检，会表现为"静默放行"而非拒绝——该风险取决于 L09 的抽取完整性 |

`L15-LIM-02` 值得记：fail-closed 的前提是**抽取不漏**。抽取漏了，守卫就看不见该拒的对象。
所以真正的护栏不是这个 if，而是 L09 的抽取测试。

但系统现在会**明确拒绝**而不是交付一个缺了脚注的包。
