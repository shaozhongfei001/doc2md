## 3. 四条设计约束，各防一种假成功

| 约束 | 它防的假成功 |
|---|---|
| `reason` + `review_decision_ref` 必填（`E_REVIEW_REQUIRED`） | 无归属决策的改动也能进产物，审计时说不清谁批的 |
| 缺 `header_rows` 直接拒绝 | 用"首行/加粗"猜表头带——L05 明令禁止的手法，换到纠错路径就复活 |
| 只有受影响表被重建，其余表 payload 逐字节不变 | "重建"退化成"全量重新生成"，与全新跑一次不可区分，影响面被掩盖 |
| `notes_rebound=False` 显式标记 | 脚注没重绑却读起来像已跟随，锚点错位无人发现 |

## 4. TL 探针抓到的缺陷（自测全绿时仍存在）

**P2**：`text` 字段被订正为整数 `150` → **放行且 `publishable=True`**。

序列化成 JSON 是 `150`（无引号），契约侧才炸，现场看起来像下游的 bug。
已加类型守卫 `type(current) is not type(value)`（用 `is not` 而非 `isinstance`，
顺带挡住 `True` 混进 int 字段），并补一例回归。

> 这是第四次"DEV 自测全绿、探针仍能进去"。稳定规律：**自测验证的是作者设想的路径，
> 探针验证的是作者没想到的输入类型**。

## 5. 新增限制

| 编号 | 限制 | 影响 |
|---|---|---|
| `L12-LIM-01` | 脚注**不重绑**（缺文档级候选集），只显式标记 | 订正涉及脚注标记位置/文本时，需重跑 notes 提取，不能只靠 `apply_correction` |
| `L12-LIM-02` | 纠错只重建语义与复核包，**候选证据/RFC6902 补丁**未随之更新 | 与 L07 的补丁链尚未贯通 |
| `L12-LIM-03` | 同一 generation 只能订正一次语义；二次订正需从新结果继续 | 多次连续订正的链式支持未验证 |

## 6. 结论

`L11-LIM-01` **关闭**：纠错现在真的产出新版本，旧代与源文件都不变。

但对外表述要限制在：**"单次、可归属、带表头带声明的订正可安全重算受影响表"**。
不等于"任意编辑都会自动保持一致"——`L12-LIM-01/02` 划掉了脚注与补丁链。
