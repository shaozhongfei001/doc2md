## 2. 红线（全程适用，任一违反即 STOP）

1. **不伪造**：缺 bbox / 缺 stats / 缺 caption 一律 `null` + 计数，禁止估算填充（D-2）。
2. **fail-closed**：schema / asset 校验不过，**绝不落盘**半成品 IR（D-3）。
3. **零迁移**：`sql/**` 任何新增文件即 STOP 报 Owner（Q8）。
4. **不动旧契约**：`parsed_text.md` / `parsed_metadata.json` 内容与 hash 不变；`parse_manifest.json` 仅 additive 字段。
5. **014 边界**：`mineru_pdf_parser.py` 只允许 §3.2 的 additive 变更；v1 行为分支逐字不动；改完必须 `git diff` 证明纯追加。
6. **`field_value` 零数据行**（Q6）、`kb_document_chunk`/`kb_evidence` 零新增列。
7. **不越界**：白名单外文件一律不改；`specs/001..016`、`specs/902` 封版不得动。
8. **留痕纯 append**：往已有文档追加时不得改写既有行；若必须更正，另起「更正」小节并说明原委。

## 3. 失败处理阶梯（无人值守自愈协议）

| 级别 | 情形 | 动作 |

| L1 自愈 | 测试红 / import 错 / fixture 构造失败 | 实现者自行修，最多 3 轮；每轮记录原因 |

| L3 回退 | 改动触及红线或破坏基线 | 回退该处改动，改为最小实现；记录 `FAIL-017-xx` |
| L4 STOP | 规格互斥 / 必须迁移 / 需要 Owner 裁定 | 停在该阶段，出「冲突说明 + 两方案 + 代价」，交 TL/ Owner |
